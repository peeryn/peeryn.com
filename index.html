AI broke trust

Deepfakes, bots, and AI-generated identities mean you can't verify who — or what — you're transacting with. Every platform is drowning in fake accounts. CAPTCHAs are dead. KYC is expensive. Trust is the scarcest resource.

Fake identities at scale

AI generates millions of convincing fake personas. Traditional identity verification can't keep up.

No agent accountability

Missing trust rails

AI agents need to negotiate, pay, and collaborate — but there's no trust infrastructure connecting them to real humans.

Proof of Peers

Instead of proof of work or proof of stake, Peeryn uses real human relationships to validate transactions. Inspired by six degrees of separation.

01

Verify in person

Users verify each other's identity face-to-face, creating a trust edge in the peer graph. Your identity is a deterministic hash of your real-world info — one person, one identity, sybil-resistant by design.

02

Build your trust graph

Each verification strengthens your position in the network. More verified friends = higher trust score. Trust is earned through real relationships, not capital.

03

Transact at trust speed

Transactions between close peers validate fast with fewer validators. Transactions between distant peers require more validation. Higher value = more validators needed. The network adapts to risk.

04

Register AI agents

Verified humans register AI agents that inherit their trust score. Agents can transact, negotiate, and pay each other — with human accountability baked in.

    Trusted Peers          Transaction Speed         Validators Required
    ─────────────          ──────────────────        ───────────────────
    Close friends    →     Instant (~1s)        →    3 neighbors
    Friends of friends →   Fast (~5s)           →    4-5 validators
    3 hops away      →     Standard (~15s)      →    6-7 validators
    4+ hops away     →     Thorough (~30s)      →    8+ validators

    Higher value transactions always require more validators,
    regardless of trust distance.

Trust Inheritance

Agents inherit trust from their verified human owner's position in the peer graph. No owner verification = no agent.

Rate Limits

Owner-configured limits: max per transaction, hourly spend, transaction count, and counterparty limits. Safety by default.

Capability Declaration

Agents declare what they can do: payments, negotiation, data queries, oracle services, contract execution.

Lifecycle Control

Owners can pause, resume, or permanently deactivate agents. Full control stays with the human.

On-chain Registry

Solidity smart contract for agent registration, payment enforcement, and trust queries. Fully auditable.

Activity Logging

Every payment, registration, and status change is logged. Full transparency for owners and counterparties.

Build with Peeryn

TypeScript SDK, JSON-RPC API, and CLI. Register an agent in 5 lines of code.

Register an AI agent TypeScript 
import { PeerynClient } from '@peeryn/sdk';

const client = new PeerynClient('http://localhost:8545');

// Register an AI agent under your verified identity
const agent = await client.registerAgent(myAddress, {
  name: 'shopping-assistant',
  description: 'Finds best deals and makes purchases',
  capabilities: ['payments', 'negotiation'],
});

// Agent can now transact with other agents
await agent.pay(otherAgentId, '2.5'); // 2.5 PYN
Verify before transacting TypeScript 
// Always verify counterparty trust before transacting
const trust = await agent.verifyCounterparty(sellerAgentId);

if (trust.valid && trust.trustScore > 30) {
  console.log(`Trusted agent (score: ${trust.trustScore})`);
  console.log(`Owner verified: ${trust.ownerVerified}`);

  // Safe to transact
  const result = await agent.pay(sellerAgentId, '10.0', 'Market data');
  console.log(`TX: ${result.txHash}`);
} else {
  console.log('Trust too low, declining transaction');
}
Run a Peeryn node Shell 
# Install and start a node
git clone https://github.com/peeryn/peeryn.git
cd peeryn && bun install

# Start the node
bun run start

# Or use the CLI
bun run cli node start --rpc-port 8545 --p2p
bun run cli account create
bun run cli peer list

Architecture

Full EVM compatibility with a DAG-based transaction layer and trust-weighted consensus.

Core

  • EVM via ethereumjs
  • DAG transaction architecture
  • LevelDB persistent storage
  • Block executor & state manager

Network

  • libp2p peer-to-peer
  • Wire protocol & sync
  • Peer discovery (mDNS, DHT)
  • Transaction propagation

Identity

  • Biometric hash (keccak256)
  • In-person verification
  • Sybil-resistant registry
  • Duplicate detection

Agents

  • On-chain registry (Solidity)
  • Trust inheritance
  • Rate limit enforcement
  • TypeScript SDK
